## Моя рефлексия

На этом практическом занятии я освоила полный цикл работы с удалённым репозиторием, настройку изолированного окружения и отправку запросов к внешнему REST API на Python, выполнив проект в связке VS Code и GitHub. Лучше всего у меня получилось настроить отправку GET-запросов к OMDb API и извлечение данных о фильмах, дополнив базовый вывод описанием сюжета (`Plot`) и списком актёров (`Actors`). Небольшое затруднение возникло при тестировании неверного API-ключа в ветке `env-feature`: скрипт продолжал возвращать данные из-за несохранённого файла `.env` и дублирующей ячейки запроса, но сохранение файла и изменение load_dotenv() на load_dotenv(override=True) решили проблему.

В ходе работы я на практике убедилась, что основная ветка (`main`/`master`) предназначена для стабильной рабочей версии проекта, тогда как отдельные ветки вроде `env-feature` позволяют безопасно изолировать эксперименты и не смешивать разные подходы к хранению ключей. Регулярные коммиты помогают фиксировать каждый логический этап разработки и при необходимости позволяют легко откатиться к исправному состоянию кода. Для управления зависимостями проекта (библиотеками `requests` и `python-dotenv`) я создала виртуальное окружение `.venv`, которое изолирует пакеты конкретного проекта от глобальной системы. Чтобы личный API-ключ не попал в публичный репозиторий и не был скомпрометирован, я вынесла его в файл `.env` и добавила этот файл в `.gitignore`, отказавшись от хранения секретов в открытом коде. Ответ от сервиса приходит в текстовом формате JSON, который по структуре напоминает словарь Python и требует разбора через `.json()` и метод `.get()`, чтобы безопасно извлечь только нужные пользователю поля без риска получить ошибку `KeyError`.

Визуальные инструменты VS Code значительно упростили работу: через встроенную панель управления версиями и интерфейс выбора ядра Jupyter было удобно отслеживать изменённые файлы, переключаться между ветками и контролировать состояние несохранённых вкладок. AI-ассистент помог провести review скрипта, указав на отсутствие обработки логической ошибки `Response == "False"` при поиске несуществующего фильма, после чего я внесла предложенный блок `try-except` и проверила работу кода на разных сценариях. Если бы я выполняла это задание ещё раз, я бы сразу вынесла логику запроса и вывода карточки фильма в отдельные функции с аннотациями типов.
